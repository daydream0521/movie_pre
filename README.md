# MovieLens Explorer

> 课程题目：**推荐系统如何“猜你喜欢”：从协同过滤到深度学习推荐**
> 用 MovieLens 100K 的真实评分，讲清 **User-CF（找相似的人）** 与 **Item-CF（找相似的电影）**，并给出可现场演示、可逐步解释、指标全部来自实跑结果的 Streamlit 应用。

## 3. 数据与划分（不掺水的地方）

| 项目 | 值 |
|---|---|
| 评分条数 | 100,000（1–5 分整数） |
| 用户 / 电影 | 943 / 1,682 |
| 评分均值 | 3.5299（4 分最多：34,174 条） |
| 矩阵密度 | 6.30%（u1.base 训练集 5.04%） |
| 每人评分中位数 | 65 |
| 每片评分中位数 | 27 |

**关于“没有评分”**：空白格只表示**数据里没有这条观测**。它可能是没看过，也可能是看过没评、或不想评——绝不能当成 0 分，也不能等同于“不喜欢”。所有均值、相似度、预测都只在有观测的位置计算。

**关于官方五折的实际结构**（实测确认，与“每用户 80/20”的直觉不同）：

- `u1.test` … `u5.test` 是 `u.data` 按记录顺序切出的 5 个连续块（各 20,000 条），`uK.base` 是其余 80,000 条；
- 因此 `u1.test` 只覆盖 **459 名**用户，`u2.test` 653 名，`u3.test` 869 名，`u4.test` 923 名，`u5.test` 927 名；
- 五个测试集互不重叠，合起来正好是全部 10 万条评分。

这一结构不影响评分预测（E1–E3）的合法性，但**影响 Top-N 评测的统计口径**：某个 fold 里没有测试记录的用户无法评估，必须在报告里单独计数（见 E4）。

## 4. 算法定义（代码、界面、报告、讲稿共用这一套）

设训练评分矩阵为 `R`，观测掩码 `M`（`M[u,i]=1` 表示评过分），`mean(u)` 只用该用户在训练集中**已观测**的评分。

**相似度**

- 用户向量：`x_u = (r(u,i) - mean(u))`，仅观测位置非零 → 余弦 = 中心化余弦。
- 物品向量：同样减去**该条评分所属用户**的均值 → 余弦 = 调整余弦。
- 收缩：`sim ← sim * n/(n+10)`，`n` 为共同评分数；`n < 3` 时置 0。对角线置 0。
- 只使用训练集评分计算；不使用类型标签或文本。

**评分预测（E1–E3 用这个）**

```
User-CF: pred(u,i) = mean(u) + Σ_{v∈N_K} sim(u,v)·(r(v,i)-mean(v)) / Σ|sim(u,v)|
Item-CF: pred(u,i) = mean(u) + Σ_{j∈N_K} sim(i,j)·(r(u,j)-mean(u)) / Σ|sim(i,j)|
```

- `N_K`：**相似度为正**、且能提供评分证据的邻居（User-CF：给 i 评过分的人；Item-CF：u 评过的电影），按相似度降序取前 K 个。
- **关于负相似度**：本实现不用它，原因是 `Σ|sim|` 归一化下负权重会把结果反向外推。这是**设计选择，不是数学必需**——保留负相似也能算，但需要重新讨论归一化方式，并接受更多越界预测。
- 无可用邻居 → 回退 `mean(u)`；用户训练集为空 → 回退全局均值；预测裁剪到 `[1,5]`。

**Top-N 排序（E4 与推荐页用这个）**

```
rank_score(u,i) = Σ_{v∈N_K} sim(u,v)·(r(v,i)-mean(v))     # 预测公式的分子，不除以 Σ|sim|
```

排序用**加权和**而不是加权平均：加权平均会把“只有 1 个弱邻居、恰好打了 5 分”的冷门片归一化成 5.00，挤掉“有 20 个邻居都打 4.5 分”的电影。实测这个陷阱会让 Item-CF 的 HitRate@10 从 0.687 掉到 0.026。

**覆盖率的统一定义**

```
CF 有效邻居覆盖率 = 测试评分中「至少用了 1 个正相似邻居完成预测」的比例 = 1 − 回退率
```

它只对协同过滤有意义；用户均值基准不需要邻居，覆盖率标记为**不适用（NaN）**，不与 CF 的覆盖率比较大小。

## 5. 实测结果（全部来自 `results/*.csv`）

**E1 五折评分预测（K=30）**

| 模型 | MAE | RMSE | CF 覆盖率 |
|---|---|---|---|
| 用户均值基准 | 0.8362 ± 0.0090 | 1.0437 ± 0.0119 | 不适用 |
| **User-CF** | **0.7295 ± 0.0048** | **0.9370 ± 0.0061** | 99.71% |
| **Item-CF** | 0.7332 ± 0.0089 | 0.9415 ± 0.0112 | 99.19% |

- 两种 CF 都比均值基准低约 0.10 RMSE；User-CF 在 5 折中的 4 折优于 Item-CF，但差距（0.0045）小于折间波动（标准差 0.006–0.011），**不能据此断言谁绝对更强**。
- 构建相似度：用户约 0.03 s / 物品约 0.05 s；2 万条测试评分批量预测 0.12–0.18 s（纯 CPU、单进程）。

**E2 邻居数 K（固定 u1）**：K 5→20 时 RMSE 明显下降（User-CF 0.9867→0.9477，Item-CF 0.9927→0.9620），K=30 最低，K=50 略回升；覆盖率几乎不变（回退只发生在“一个邻居都没有”时）。

**E3 训练记录减少（固定 u1，保留 100%/50%/25%）**：保留 25% 时 User-CF RMSE 0.9472→1.1145、覆盖率 99.69%→78.56%；Item-CF RMSE 0.9604→1.1804、覆盖率 99.18%→76.02%。

**扩展：Bias-MF（矩阵分解，ALS，同一五折与同一任务）**

| 模型 | MAE | RMSE | 训练时间 |
|---|---|---|---|
| 用户均值基准 | 0.8362 ± 0.0090 | 1.0437 ± 0.0119 | — |
| User-CF | 0.7295 ± 0.0048 | 0.9370 ± 0.0061 | 约 0.03 s |
| Item-CF | 0.7332 ± 0.0089 | 0.9415 ± 0.0112 | 约 0.05 s |
| Bias-MF（扩展） | **0.7225 ± 0.0062** | **0.9202 ± 0.0072** | 约 3.8 s/折 |

评分预测上 Bias-MF 更好，但它**不参与演示界面**（无法指到“是谁影响了预测”），也没有做 Top-N 与 NCF 对照。

**E4 Top-10 推荐（5 折，候选 = 全部未评分电影，相关 = 测试评分 ≥4）**

| 模型 | Recall@10 | NDCG@10 | HitRate@10 | 推荐物品覆盖率 | 触及电影数 |
|---|---|---|---|---|---|
| 热门推荐 | 0.1361 ± 0.0111 | 0.1982 ± 0.0326 | 0.6883 ± 0.0760 | 4.03% | 67.8 |
| User-CF | **0.1417 ± 0.0110** | 0.2367 ± 0.0371 | **0.6967 ± 0.0619** | 10.17% | 171.0 |
| Item-CF | 0.1393 ± 0.0097 | **0.2435 ± 0.0365** | 0.6872 ± 0.0646 | **32.28%** | 543.0 |

- 三者的 Recall/HitRate 很接近（差异在 0.01 量级）；**NDCG 上 Item-CF 最好**，说明它把命中的电影排得更靠前；热门推荐的 NDCG 最低。
- 热门推荐只推了 68 部不同的电影（覆盖 4.0% 目录），Item-CF 推了 543 部（32.3%）：命中率接近，但多样性差 8 倍——这是“热门推荐看起来不差，其实没有个性化”的直接证据。
- 每折平均有 176.8 名用户在该折没有测试记录、22.8 名用户有测试记录但没有 ≥4 分的电影，这两类都不进入均值。

## 7. 正确性自查（对应验收标准）

| 验收点 | 如何保证 |
|---|---|
| 推荐不含已看电影 | `recommend()` 候选集 = `~M[u]`；`test_recommend_excludes_seen_items` |
| 预测只用训练集 | 模型只由 `uN.base` 构建；`test_test_ratings_never_in_training_matrix` |
| 空评分不是 0 分 | 均值/相似度只对 `M` 生效；`test_missing_is_not_zero` |
| 无邻居要标注回退 | `PredictionResult.is_fallback` + 卡片徽标；`test_no_neighbor_falls_back_to_user_mean` |
| 教学第 3 步 = 第 4 步 | `test_step3_neighbors_equal_step4_neighbors`（2 算法 × 5 用户 × 5 影 × 4 个 K 全组合） |
| 已评分目标要隐藏 | `test_rated_target_is_hidden_from_matrix` |
| 覆盖率不与基准比较 | 基准 `coverage=NaN`；`test_baseline_has_no_coverage` |
| 排序用加权和 | `test_recommend_ranks_by_weighted_sum` |
| 公式与界面一致 | `explain()` 与手算页同源；3 项公式测试 |
| 随机换用户真的生效 | 冒烟测试断言 selectbox 值发生变化 |
| 结果是真跑的 | E1–E4 写 CSV，页面只读 CSV；报告数字逐条对上 |

## 8. 已知限制

1. **E4 的“相关”只来自测试集正例**：只把评过 ≥4 分的电影当作相关，没出现在测试集的电影既不算相关也不算负反馈。它衡量“能不能在 10 个位置里捞到已知的好片”，不是点击率或用户满意度。
2. 官方五折是按记录切块的，单个 fold 只覆盖部分用户（u1 仅 459 人），跨折平均才接近全量用户。
3. 评分预测误差低 ≠ 推荐体验好：E1 与 E4 是两个任务，必须分开看。
4. 完全冷启动（0 条交互的新用户/新电影）在 CF 下无解，只能回退均值；矩阵分解同样解决不了“零交互”这一情形。
5. 相似度为静态计算，未建模用户口味随时间的漂移（时间戳未使用）。
6. 做了 Bias-MF 的评分预测对照（见上表），但**没有做 NCF**，也没有做 MF 的 Top-N 评测，因此不对深度学习与传统 CF 的总体优劣下结论。
