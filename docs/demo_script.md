# 课堂演示操作说明（90 秒版）

> 默认打开就是「课堂演示」第 1 步，不需要选用户、调 K、切算法，也不用打开侧边栏。
> 演示地址：`http://localhost:8501/`（`python -m streamlit run app.py` 启动）。

---

## 1. 固定案例（由真实数据选出，非硬编码）

| 项目 | 值 | 说明 |
|---|---|---|
| 用户 | **用户 1** | `u1.base` 中有 135 条训练评分，评分均值 3.68 |
| 历史高分 | Star Wars (1977)、Return of the Jedi (1983)、Toy Story (1995) | 5 分片中按“被评分次数”取前 3，保证同一份数据每次都一样 |
| User-CF Top-3 | Raiders of the Lost Ark / Silence of the Lambs / Usual Suspects | K=30，与完整实验同一函数 |
| Item-CF Top-3 | Raiders of the Lost Ark / Shawshank Redemption / Schindler's List | 同上 |
| 共同项 | 1 部（Raiders of the Lost Ark） | 选了“共同推荐里两边邻居都最多”的那部做第 3 步 |
| 解释页证据 | 左：用户 653 / 868 / 896（都打 5 分，贡献 +0.071 / +0.071 / +0.067）<br>右：Star Wars / Empire Strikes Back / Return of the Jedi（都打 5 分，贡献 +0.085 / +0.080 / +0.069） | 全部为运行时现算 |

> 三条推荐、四个邻居、每个贡献值都由 `src/demo.py` 在页面加载时调用 `CFModel` 算出；`build_case` 只做挑选，不改分数。

## 2. 90 秒脚本（照着点、照着说）

| 时间 | 你点哪里 | 你说什么（一句话） |
|---|---|---|
| 0:00 | 打开首页，停在第 1 步 | “先看一个人：这是 MovieLens 里的真实用户，他在训练集里评过 135 部电影。” |
| 0:10 | 指着三张卡片 | “这三部他都打了满分——《星球大战》《绝地归来》《玩具总动员》。” |
| 0:22 | 指着结论条 | “他打过 4 分以上的 84 部里，出现最多的类型是剧情、喜剧、爱情。” |
| 0:30 | 点 **下一步 →** | “现在让系统给他推荐。” |
| 0:33 | 停在第 2 步，先指左栏 | “左边 User-CF：找和他口味相似的人，再问这些人看了什么。” |
| 0:42 | 指右栏 | “右边 Item-CF：不找人，找他看过的片里，哪些和候选电影相似。” |
| 0:52 | 指“共同”标签 | “六个位置只有《夺宝奇兵》重合，其余四部完全不同——两种方法看的不是同一件事。” |
| 1:00 | 点 **下一步 →** | “那为什么都推《夺宝奇兵》？看证据。” |
| 1:03 | 指左列 | “左边是人的证据：这三位相似用户都给它打了 5 分。” |
| 1:12 | 指右列 | “右边是电影的证据：他打 5 分的星战三部曲，和这部片最相似。” |
| 1:22 | 指结论条（可选：展开“查看计算过程”） | “两条证据链指向同一个推荐；末尾的 +0.08 是每个邻居对预测分的实际影响。” |
| 1:28 | 点 **重新演示** | “换一部片，同样的三步可以再走一遍。” |

**只用三个按钮**：上一步 / 下一步 / 重新演示。其余操作都是“指一下、说一句”。

## 3. 默认页移走了什么，放到了哪里

| 原来在默认页的内容 | 现在的位置 |
|---|---|
| 数据集规模、评分分布、密度 | 完整实验 → **概览** |
| 5×5 矩阵、相似度表、Top-K、手算复核 | 完整实验 → **原理实验室** |
| 换用户、切算法、调 K、Top-10/20、双算法对比、单条解释 | 完整实验 → **电影推荐** |
| MAE / RMSE / CF 覆盖率 / Recall / NDCG / 实验图表 | 完整实验 → **实验结果**（E1–E4） |
| 预测公式、Σ\|sim\|、邻居上限 K=30、完整邻居表 | 课堂演示第 3 步 → **查看计算过程**（折叠） |
| 矩阵分解 / NCF 的概念与 Bias-MF 实测 | 完整实验 → **从 CF 到深度学习** |

入口：课堂演示页右上角的 **完整实验 →**（文字链接，不占主操作位）。

## 4. 验收记录

运行环境：Windows，Python 3.12.7（conda base），Streamlit 1.37.1，Chrome headless 1366×768 / 1920×1080。

**首屏可读性与滚动检查**（`scripts/shot_demo.py` 实测 `scrollHeight` 与可视高度）：

| 尺寸 | 第 1 步 | 第 2 步 | 第 3 步 |
|---|---|---|---|
| 1366×768 | 768 / 768，无需滚动 | 768 / 768，无需滚动 | 768 / 768，无需滚动 |
| 1920×1080 | 1080 / 1080，无需滚动 | 1080 / 1080，无需滚动 | 1080 / 1080，无需滚动 |

截图（`docs/screenshots/`）：

- `demo-1366x768-step1.png` / `step2` / `step3`
- `demo-1920x1080-step1.png` / `step2` / `step3`

**逐项自查**：

| 检查项 | 结果 |
|---|---|
| 默认进入第 1 步 | 是（`nav_mode` 默认「课堂演示」，`demo_step` 默认 0） |
| 主操作只有三个按钮 | 是；第 1 步「上一步」禁用，第 3 步变「重新演示」 |
| 默认不出现 RMSE / 覆盖率 / 公式 | 是（冒烟测试断言页面文本不含 “RMSE”“覆盖率”） |
| 两种算法并排可读 | 1366 下两栏各 3 行，标签「共同 / 仅 User-CF / 仅 Item-CF」不换行 |
| 负贡献符号 | 贡献为负时显示 `−0.0xx` 且为红色 chip（本案例展示的前 3 名均为正贡献，完整表内存在 −0.01 量级负值） |
| 贡献之和与预测分对账 | 展开区写明“表格只列前 3 名，不能直接相加”，并给出 `均值 + 全部 30 个邻居贡献 = 预测分` 的完整算式 |
| 第 1 步结论有数据支撑 | “4 分以上 84 部，类型计数 Drama 42 / Comedy 26 / Romance 17”，只做计数陈述 |
| 视觉体系统一 | 演示页与完整实验共用 `src/ui.py` 的 token（#141c24 画布、#efb85b 主操作、#67c6c0 对照）、同一套卡片与按钮 |

**一句话结论**：三步在 1366×768 与 1920×1080 下均无需滚动即可读完，主操作只有两个按钮，技术细节默认折叠。
